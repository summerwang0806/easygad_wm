# ACL 基线：Dipper 普通 UP 改写

本目录实现蒸馏前的普通、非针对性改写（Untargeted Paraphrasing，UP）：使用 **Dipper** 改写已有 KGW 教师回答，再将改写后的训练集用于 Warmup 和 GAD。这里不是让其他聊天模型重新回答问题，也不在生成时注入逆水印。

所有命令都从 EasyGAD 项目根目录执行：

```bash
cd /app/wwx/EasyGAD
conda activate wm
```

服务器上的 `/app/wwx/EasyGAD` 与 `/shared/wwx/EasyGAD` 指向同一份项目。根目录的综合运行说明见 [UP_BASELINE.md](../UP_BASELINE.md)。本文不包含账号密码或 SwanLab 密钥。

## 1. 与 ACL 论文的关系

参考论文：[Can LLM Watermarks Robustly Prevent Unauthorized Knowledge Distillation?（ACL 2025）](https://aclanthology.org/2025.acl-long.648/)。

- 论文 §3.3 将 UP 定义为直接用改写模型重写训练数据，§4.1 指定改写器为 Dipper。
- 论文没有明确披露 UP 是逐句、三句分块，还是整条回答一次改写。[ACL 作者仓库](https://github.com/THU-BPM/Watermark-Radioactivity-Attack#attack-pipeline)公开实现只覆盖 WN，UP、TP 的改写模块需自行接入。
- [Dipper 官方代码](https://github.com/martiansideofthemoon/ai-detection-paraphrases/blob/main/dipper_paraphrases/paraphrase_minimal.py)默认每三句一批，使用前面生成的改写作为后续上下文。它也会处理全部句子，并非只改前三句。
- **本项目按当前实验要求改为整条回答一次改写**，输出预算也相应提高。因此这是对普通 UP 方法的重新实现与项目适配，不声称逐项精确复现 ACL 未公开的实验参数。

实验记录可表述为：“采用 Dipper 实现普通 UP；每条教师回答整体改写一次，使用下述固定采样配置。”本目录目前不实现 TP 或 WN。

## 3. 当前改写逻辑与默认参数

每条回答先归一化空白，再用 NLTK 英文分句，将**全部句子拼接成一个完整输入**，调用 Dipper 一次。分句用于预处理和统计，不再控制生成批次；不逐句生成，不按三句分组，不使用滚动 prefix，也不把原问题或其他样本放进 prefix。

输入形式为：

```text
lexical = 40, order = 100 <sent> 本条教师回答的全部句子 </sent>
```

内部控制码是 `100 - diversity`，上述输入对应 lexical diversity=60、order diversity=0。

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 模型 | `kalpeshk2011/dipper-paraphraser-xxl` | Dipper 11B T5 encoder-decoder |
| Tokenizer | `google/t5-v1_1-xxl` | 使用本地 T5Tokenizer |
| lexical / order diversity | 60 / 0 | 参考作者模型卡示例，不是 ACL 明确披露的参数 |
| `--max-input-tokens` | 4096 | 完整输入含控制码与 encoder EOS；超限报错，不截断或拆块 |
| `--max-output-length` | 4096 | decoder 总长度上限，包含初始 start token；不是要求生成满 4096 |
| `--top-p` / `--top-k` | 0.75 / 0 | 采样并禁用 top-k 筛选 |
| `--temperature` / `--seed` | 1.0 / 42 | 固定记录的采样参数 |
| `--dtype` | `float32` | 可显式改为 `bfloat16`，需记录精度适配 |
| `--batch-size` | 1 | 进度分组的行数，不是 GPU 并行批量推理；回答仍依次生成 |
| `--max-attempts` | 1 | 默认每条只尝试一次，不按水印或质量指标选样本 |
| `--on-failure` | `error` | 无效输出停止任务，不偷偷补原文或丢行 |

整篇改写**不保证句数相同**，可能合并、拆分或压缩句子。正常生成 EOS 也不证明语义完整；换行、列表或代码排版可能因空白规范化而改变。需要事后抽查数字、实体、事实与条件是否保留。

## 5. 先做 CPU 预检

```bash
# 只检查原始 Parquet，不加载 tokenizer 或模型。
python baseline_acl/paraphrase_up.py \
  --input data/dolly15k_qwen2_5_14b_kgw_train.parquet --inspect

# 使用小型 tokenizer 与 NLTK，检查每条完整输入的长度。
python baseline_acl/paraphrase_up.py \
  --input data/dolly15k_qwen2_5_14b_kgw_train.parquet --preflight
```

`--preflight` 不需要 Dipper 权重，不占 GPU、不写改写数据。发现输入超限时直接报错；它不会自动切回三句窗口。更换数据或参数后应重新检查。

## 6. 正式改写

下面示例显式选择 1 号 GPU。运行前自行确认或协调显存，不使用 0 号卡，不停止其他同学的任务。Dipper 要求恰好一张可见 GPU；float32 权重本身约 45 GB，实际推理还需额外显存，不能按权重大小判断一定能跑。

```bash
CUDA_VISIBLE_DEVICES=1 python baseline_acl/paraphrase_up.py \
  --input data/dolly15k_qwen2_5_14b_kgw_train.parquet \
  --output data/dolly15k_qwen2_5_14b_kgw_up_dipper_train.parquet \
  --model baseline_acl/models/dipper-paraphraser-xxl \
  --tokenizer baseline_acl/models/t5-v1_1-xxl-tokenizer \
  --dtype float32 \
  --lex-diversity 60 --order-diversity 0 \
  --max-input-tokens 4096 --max-output-length 4096 \
  --top-p 0.75 --temperature 1.0 --seed 42 \
  --max-attempts 1
```

如使用空闲 40GB 卡，可显式改为其他已协调的 GPU 与 `--dtype bfloat16`，例如 `CUDA_VISIBLE_DEVICES=3`。这只是资源适配，仍不保证当前空闲显存足够；实验中应记录精度。

完成后输出：

```text
data/dolly15k_qwen2_5_14b_kgw_up_dipper_train.parquet
data/dolly15k_qwen2_5_14b_kgw_up_dipper_train.parquet.progress.jsonl
data/dolly15k_qwen2_5_14b_kgw_up_dipper_train.parquet.audit.json
```

默认模式下，所有行成功后才发布完整 Parquet；JSONL 保存逐行进度，audit 记录参数、拒绝原因、改写数量和字段保护检查。audit 不证明水印已经洗净或语义完全保留。

### 中断与重跑

中断后使用**完全相同的生成命令，加 `--resume`**。输入、模型、tokenizer、NLTK 资源与生成配置必须匹配，已成功的行不会重做。当前为 v3 断点格式，旧 Qwen 或三句版本断点不能续接。

若失败已耗尽尝试次数，同参数 `--resume` 不会自动增加尝试。应先查看失败记录；如决定改变参数或使用显式 `--max-attempts 3`，请使用新输出文件名。`--on-failure keep-original` 会混入未改写原文，不建议用于正式纯 UP 对照实验。

已有输出不会覆盖。采用新文件名时，后续训练用 `--up_train_file 新文件路径` 指定它。不要删除或移动他人的文件。

## 8. 两组 Warmup + GAD 训练

| 实验 | Warmup 数据 | GAD 数据 | 轮数 |
| --- | --- | --- | --- |
| A：`up_up` | Dipper-UP | 同一份 Dipper-UP | 1 epoch + 1 epoch |
| B：`up_kgw` | Dipper-UP | 原 KGW | 1 epoch + 1 epoch |

两组的两个阶段均使用未改写的原 KGW test 验证。学生和未另行指定的独立 critic 从原始 `/shared/public_models/Qwen2.5-0.5B` 初始化；Warmup 完成后合并本组 actor/critic checkpoint，交给本组 GAD，不加载旧 SeqKD 学生。

先检查训练配置。`--dry_run` 仍要求完整 UP 文件存在并通过 CPU 数据校验，但不会启动训练或连接 SwanLab：

```bash
CUDA_VISIBLE_DEVICES=1,3 bash scripts/train/run_full_gad_up_up_optimized.sh \
  --exp_name kgw_up_dipper_up_1ep --nnodes 1 --dry_run

CUDA_VISIBLE_DEVICES=1,3 bash scripts/train/run_full_gad_up_kgw_optimized.sh \
  --exp_name kgw_up_dipper_kgw_1ep --nnodes 1 --dry_run
```

去掉 `--dry_run` 正式运行。先结束改写，再依次跑两组训练，不要在同样的 GPU 上同时启动这些任务：

```bash
# A：洗过的 Warmup + 洗过的 GAD。
CUDA_VISIBLE_DEVICES=1,3 bash scripts/train/run_full_gad_up_up_optimized.sh \
  --exp_name kgw_up_dipper_up_1ep --nnodes 1

# B：洗过的 Warmup + 原 KGW GAD。
CUDA_VISIBLE_DEVICES=1,3 bash scripts/train/run_full_gad_up_kgw_optimized.sh \
  --exp_name kgw_up_dipper_kgw_1ep --nnodes 1
```

如果只有一张可用卡，显式选择该卡并加 `--gpus_per_node 1`。改变改写输出文件名时，两组入口均加 `--up_train_file 路径`。重跑训练使用新的 `--exp_name`，不要覆盖已有实验。

包装入口复用 `scripts/train/run_full_gad_all_clean_optimized.sh` 的学习率、batch、训练长度、显存与 SwanLab 配置。其文件名和旧 CLEAN 日志标签不代表本次数据，实际数据以明确传入的阶段路径为准。训练回答超过现有 1536 个学生 token 上限时仍按原加载器右截断；它与 Dipper 的 4096 个 T5 token 预算不是同一个限制。

SwanLab 记录沿用已有脚本的认证和网络设置；本模块不新建密钥配置。每组实验的阶段名称为 `<exp_name>_warmup` 与 `<exp_name>_gad`。checkpoint 位于：

```text
checkpoints/<exp_name>/warmup/global_step_*/{actor,critic}/
checkpoints/<exp_name>/gad/global_step_*/{actor,critic}/
```

两套入口各自独立训练 Warmup，不共享同一 Warmup checkpoint。如果需要严格对比同一起点的 GAD 分支，要另行设置共享起点实验，不能把两次独立 Warmup 当作完全相同的模型。

## 9. 验证记录与实验注意事项

2026-10-09 已完成整篇模式的服务器 CPU 验证：37 项专项测试全部通过；原训练集 14,511 条回答对应 14,511 个完整输入，最多 119 句的回答也不拆块，控制码输入最长 2,149 个 T5 token，原回答最长（含 EOS）2,131 token，均未超过当前预算。这些是该批输入与代码的验证记录，不是实际 GPU 改写性能或训练完成证明。

可在 `wm` 环境运行专项测试，不需要 GPU 或 Dipper 权重：

```bash
CUDA_VISIBLE_DEVICES="" PYTHONPATH=. python tests/test_paraphrase_up.py -v
```

正式结果至少区分两个问题：改写数据本身是否降低了水印，以及训练后学生输出是否仍继承水印。与此同时检查回答质量，不能把“检测率降低”单独等同于攻击成功。句数变化本身不是质量结论，应结合事实保留、回答完整性、长度、重复率和共同参考下的质量指标分析。

`--window-size`、`--engine`、`--gpu-memory-utilization` 等旧改写参数不适用。训练包装入口自己的 `--gpu_memory_utilization` 是训练阶段 vLLM 的设置，与 Dipper 改写器无关。所有生成与训练都需手动启动，写入或阅读本 README 不会自动执行它们。
