检查日期：2026-11-03。原始断点和训练数据均未修改。源 Parquet 的 SHA-256 与断点元数据一致，因此下面的对照使用完全匹配的原文。附件快照略早于用户最新日志。

## 结论

当前配置不适合直接继续全量生成训练数据。速度主要受到少数极长失败生成的拖累；同时，通过格式检查的结果中仍有事实漂移、内容丢失和提示语污染。不能把 `ok` 当作语义保真或去水印成功。

## 人工原文对照发现

以下行号从 0 开始，均可在 samples.md 查看原文和生成结果。

- row 4：转述基本保留解释和例子，说明并非所有结果都不可用。
- row 200 (`ok`)：原文把学位归于 Springfield College；输出在 Cushing Academy 条目中加入“转去获得该学位”的信息，并遗漏原文毕业年份等细节，改变了教育经历的对应关系。
- row 600 (`ok`)：原文年代为 70–66 million years，输出变为 150 million years；相对原文发生明确数值漂移。
- row 800 (`ok`)：407 token 原文被压缩为 79 token，列举标题基本保留，但多数具体方法和限定内容消失，实际更接近摘要。
- row 904 (`ok`)：单句回答后混入关于转述规则的说明及 `You are an AI assistant...`，会污染训练回答。
- row 20 (`rejected`, 4096 token)：131 token 原文被扩写为大量年份与反复循环的句子，直至长度上限。
- row 100 (`rejected`, 4096 token)：完整信件后不断重复 `Rewritten answer:` 和改写信件。
- row 771、425 (`ok`)：超长扩写和模拟对话/任务指令也能在自然 EOS 后通过目前检查；因此仅加强截断检查仍不够。

另用固定 seed 20261103 从 750 条 `ok` 中随机抽取 20 条做原文对照，行号见 summary.json。抽样中有内容缺失、原文外扩写和提示词污染。未对全体语义作完整标注，因此不报告全体语义合格率，也不以这些示例证明某一模型或 TP 方法普遍无效。

## 代码层面的速度放大因素

当前每张 GPU 每次只生成一条回答；StudentGenerator.generate 对行逐条调用 model.generate。两卡提供两条同时进行的解码，不是大批量推理。配置为 FP32。每步反向规则处理还会在 CPU 构建全局惩罚字典、组合上下文规则、构造惩罚 tensor 并传入 GPU，且提取最后的上下文 token 到 Python。这些是可见的性能开销，但未做 GPU profiling，不能给出它们各自的耗时百分比。

基于最新日志 759 / 14511、elapsed=18917.2s，累计有效完成速度约 144.4 条/小时；线性外推剩余约 95.2 小时（约四天）。由于尚有后续重试、样本长度变化，该值只作粗略预算。

## 后续处理建议

先暂停当前全量任务并保留断点。先用小样本验证保真改写，再决定是否扩大到全量。优先处理失控续写/循环、正确的回答结束、与原文长度相适应的生成预算和语义保留；随后优化规则缓存和推理批处理。降低精度或单纯降低 max_new_tokens 都不能修复已发现的事实漂移，过低上限还会截断正常长回答。更换模型、prompt 或采样配置应作为新实验写入新输出路径，不能混入旧断点。

本次没有运行新 GPU 生成或 KGW 前后检测；无法从这份断点确认去水印效果。
